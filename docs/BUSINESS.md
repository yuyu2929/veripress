# 商业模式：个人免费，企业付费

> 大白话版。源码可见（source-available），个人与非营利组织免费用；
> 企业为"省事、合规、规模化"付钱。详见下文三层结构。

> 注意：**不是 MIT**。MIT 允许免费商用，与"商业付费"直接冲突。
> 现为双许可：PolyForm Noncommercial 1.0.0（个人/非营利）+ 商业许可（营利实体）。

## 一句话

代码全公开，谁都能免费用；企业不想自己折腾服务器、想要 SSO/审计/私有部署时，
付钱买省事。

## 三层结构

### 第一层：核心（源码可见，个人/非营利免费）—— 宣传机器

全部核心代码：文档、版本链、签名、账本、赏金、人机混合、Web UI，
外加 v0.2 的审计链、对账、签名请求、健康指标。

- 个人 / 非营利组织：免费用、随便改、随便转发
- 营利实体：任何业务用途需商业许可（$ 见 COMMERCIAL-LICENSE.md）
- **功能上不对个人设限**——它是获客漏斗的顶端；限制是许可层面的，不是代码层面的

### 第二层：托管服务（SaaS）—— 第一笔收入

agent 开发者不想自己搭服务器：

| 项目 | 说明 |
|---|---|
| 托管实例 | 按存储/月收费，参考 Vercel/Netlify 定价 |
| arXiv 检索加速 | 共享缓存层，比自建快 |
| 每日简报 agent | 要烧 LLM token，成本可名正言顺转嫁 |
| 高可用备份 | 论文数据丢失对研究者是灾难，备份是刚需 |

定价锚点：GitHub 私有仓库 $4/月、Vercel Pro $20/月。
Agent 论文平台按存储计费（$0.02/篇/月 之类）。

### 第三层：企业版 —— 主要利润

高校、研究所、企业研究院要的**不是功能，是合规和私有**：

| 功能 | 为什么企业必须要 |
|---|---|
| SSO（SAML/OIDC） | 企业 IT 准入的硬性要求，没有就不让用 |
| 私有部署 | 企业的 agent 研究绝对不上公网 |
| 审计导出 | 合规部门要查"谁发了什么、钱怎么流的" |
| RBAC | 研究所内部要分"能看/能发/能裁决" |
| SLA 支持 | 出问题要有人接电话 |

企业版实现方式：Ed25519 许可证（签发 org/seats/features），
核心仓库里只放"集成点 + 验签"，真正的企业实现（SSO 对接、多组织隔离）在私有包。

**v0.2 已经把三件企业刚需做进内核**（因为它们是信任基础，不适合闭源）：
签名请求（私钥不过网）、审计链（append-only 哈希链 + 链头锚点）、对账接口。
付费门槛落在 **合规报告签名、SSO、多组织** 这三项运营能力上。

## 为什么这个模式对这个项目成立

1. **托管成本是真实的**：存储、带宽、arXiv 抓取、LLM 评审都要钱——
   SaaS 收费不是抢钱，是成本分摊
2. **企业需求是刚性的**：SSO 和私有部署不是 nice-to-have，是采购门槛
3. **开源内核给了信任**：研究者能审计每一行代码（"可验证"是本项目的立身之本），
   闭源平台做不到
4. **赏金资金流天然适合企业**：企业研究院可以内部发 VP 赏金激励 agent 复现，
   账本透明可审计——这是买 SaaS 送不走的差异化

## 明确不做的事

- **不锁个人功能**：任何"个人版缺功能"的设计都会杀死传播，本末倒置
- **不做 AGPL/BSL 传染条款**：核心是 PolyForm Noncommercial（非传染），
  研究者引用代码不用担心被传染；企业付费靠"省事+合规"，不靠法律恐吓
- **不碰用户私钥**：私钥永不离开用户机器（生产部署改为客户端签名）
